UI Design Lab — TextBox / Text Input

Working visual specification and state laboratory for the TextBox / text input component.

Current design hypothesis: Text inputs should remain restrained and information-dense, with the border and focus treatment doing most of the work of communicating editability and interaction. Persistent color should be used sparingly.

4. TextBox Design Questions

Items that should be settled before TextBox becomes a finalized component specification.

  1. Should the normal TextBox use a clearly visible border, a subtle border, or a mostly surface-based treatment?
  2. Should the hover state use the same very-light Claro Blue surface established for appropriate controls, or should TextBox use a different treatment?
  3. Should focus change the border, add a focus ring, or use both?
  4. Can focus be unmistakably different from hover without excessive visual weight?
  5. Should the border become more prominent when the TextBox contains a value?
  6. What is the appropriate placeholder contrast relative to entered text?
  7. How should labels relate spatially and visually to the input?
  8. How should required fields be indicated?
  9. How should helper text and validation messages affect spacing and density?
  10. What is the visual distinction between Disabled and Read-only?
  11. How should Error and Warning states interact with Focus-visible?
  12. What control heights correspond to Compact, Default and Comfortable density?
  13. What border radius and horizontal padding should become shared control primitives?
  14. Which TextBox decisions should become global semantic tokens?

5. Content and Typography Questions

  • Primary entered text versus placeholder text
  • Long values and overflow behavior
  • Selection and caret visibility
  • Password input treatment
  • Numeric, date and other specialized text inputs
  • Icon or affordance placement where applicable

6. Accessibility and Keyboard Questions

  • What receives focus?
  • Is focus-visible clearly distinguishable?
  • Does Tab order remain predictable?
  • Are disabled and read-only states communicated correctly?
  • Are validation states communicated through more than color alone?
  • Does the label remain programmatically associated with the input?

8. Current Decisions

These are working decisions and hypotheses. Promote them into Design_System.html only when they are sufficiently established across the component system.

  • D-001: The TextBox should remain visually restrained in its normal state.
  • D-002: Persistent color should not be used merely to establish editability when border and typography provide sufficient affordance.
  • D-003: Hover should provide a perceptible but restrained change.
  • D-004: Focus-visible must be unmistakably different from hover without introducing unnecessary visual noise.
  • D-005: Validation states must not rely on color alone.
  • D-006: Semantic tokens should be used even when initial values remain provisional.

9. Notes for Future Iterations

This Lab is intentionally not a final implementation. It is the place where visual hypotheses can be tested before they become design-system rules.

Particular attention should be paid to the relationship between the TextBox's normal border, hover treatment and focus-visible treatment. These states should form a coherent progression rather than three unrelated visual styles.

Once the TextBox design is sufficiently settled, the final decisions should be promoted to Design_System.html and the provisional values in this Lab should be replaced with the approved semantic tokens.

The same Lab pattern should subsequently be used for Select, Checkbox, Menu, Dialog, Grid and other representative components.
