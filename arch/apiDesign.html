I have built REST APIs for my apps before. Currently I'm working on a dotnet app with FSharp/PostgreSQL on the back-end. In order to not have to rewrite the auth by hand I'm going to port Blazor's auth system (with ~20 api end points) to my minimalAPI dotnet app using a table in _my_ PostGres as the User Directory (also saves UserSettings, colorPrefs, colWidths, etc.)
Most of the end points are working and testing OK with a mock backEnd. I have two clients: desktop/web. [The app is an app builder like replit/loveable BUT much more feature-rich, like VB6 or LotusNotes.] The desktop is the 'designer client' (for use by devs) and will basically just do CRUD ops on 'Design Documents' saved on the server.
The web cli is for users to access the apps created by the devs; and most API endpoints will serve basic CRUD requests with _some_ differences: the very first request (wake from disconnected session OR first login to establish session) where the back-end is hit more than once & the logic goes something like: 
[User logged in sucessfully]
-> Retrieve UserSettings
-> Chk lastOpen DataView 
-> Retrieve UserCustomizations (if any)
-> Build Page (apply customizations if exist)
[AND NOW the standard flow for all requests]
-> Retrieve User ACL for this Table/this DataView 
-> Filter data through ACL (hides fields with no access)
-> Build HTML 
-> Serve/Handle

Now, I haven't read REST API Architecture since many years. No particular need to "make it standard for ease of fellow coders" or "make it standard to confirm to industry practise" BUT I always like to use Abstractions which help conceptualize code flow OR make separation of concerns easier.
Given that, cld you pls suggest some articles I shd read before beginning to design the API? Thx in advance.
